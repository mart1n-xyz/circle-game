# Review decisions

**Status:** all defaults below are proposals for the game unless explicitly identified as a user requirement or a source requirement. Creating this repository does not approve an implementation. A subsequent build request authorizes implementation under the reviewed plan; routine choices should not produce repetitive approval requests.

The most consequential review points are the participation format, governance, withdrawal policy, loan/pledge accounting, and the credibility mechanism. Numbers are fictional balancing inputs, not recommendations for a real mutual.

## What needs defining first

1. **Loan contracts:** what determines total borrowing capacity, required backing, rates, repayment dates, and permitted project use (D02/D04/D09).
2. **Collective decisions:** which active members vote, the approval threshold, and how several approved loans compete for limited funds (D03).
3. **Contributions and access to money:** the participation floor, lapse timing, savings withdrawal policy, and treatment of pledged funds (D02/D03/D05).
4. **Failure and loss:** when arrears become default, the exact accounts charged, and what happens to an unpaid borrower's obligation (D04/D06).
5. **Information and credibility:** what the applicant knows, what they may omit or misstate, what others can verify, and how the estimate/reputation changes (D08).
6. **Competition and completion:** shared rooms or separate comparable runs, human/bot participation, and how remaining projects and debts are valued at the finish (D01/D10/D11).

These are behavioural rules, so they should be coherent before the first playable loop is coded. Starting balances, loan rates, project frequencies, and season length can remain configurable demonstration values during balancing. The detailed federation, check, and sponsor gaps must be resolved before the corresponding P3 mechanisms are implemented; they do not need to stall a local P1 prototype.

## Confirmed direction

- Start as an existing circle member with funds already allocated, monthly contributions, and separate personal saving.
- Offer personal outside investments with uncertain returns, funded by own cash and/or circle loans.
- Let members assess and decide other members' applications with credibility-dependent information and strategic ambiguity.
- Allow contribution/saving adjustments. Use the same rules for all participants and include a leaderboard.
- Demonstrate the supplied model, including its ordinary benefits and wider network mechanics.
- Prepare this private documentation repository now; wait for a later request to build.

## Source gaps that must stay visible

The source itself lists admission/share timing, exit terms, failed-check consequences/pass duration, internal oversight, auditor compensation, multiple-parent sponsorship, and reward/charge priority as unstated. It also leaves governance and every numerical parameter unfinished. Keep their decisions traceable even when a playable default is selected.

Section 16.5 subtracts loan losses in surplus and separately mentions losses charged to reserve. The implementation must disambiguate posting and timing so the same loss is never charged twice. This is an accounting interpretation to validate, not permission to rewrite the original document.

The underlying `design-model.md` and `abstract-model.md` are not in the supplied upload. If provided later, reconcile them before declaring full fidelity to those separate documents.

## Recording review outcomes

For each changed decision, record the selected rule, who requested it, its source classification, and the affected requirements/tests. Keep past room rules available for replay. A gameplay convenience should never silently become a claim about what the institutional blueprint decided.
